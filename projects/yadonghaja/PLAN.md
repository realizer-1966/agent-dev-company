# 야!동하자 (Ya! Donghaja) 기획안 v1.0

> 운동 메이트를 모집하고, 서로 격려하고, 미션을 수행하면 보상을 주는 모바일 웹앱

- **작성일**: 2026-08-29
- **상태**: 초안 (검토 대기)
- **작업명**: 야!동하자 (Ya! Donghaja) — 정식 명칭. 좁은 표기 공간(앱 타이틀·아이콘·페드 헤더 등)에서는 **야!동** 으로 축약

---

## 1. 프로젝트 개요

### 한 줄 정의
"혼자 하면 포기하기 쉬운 운동을, **메이트와 함께 미션으로 달성**하고 **포인트·배지·랭킹**으로 보상받는 모바일 웹앱"

### 해결하려는 문제
| 페인 포인트 | 해결 |
|---|---|
| 혼자 운동하면 3주 안에 포기한다 | 메이트 모집 → 약속이 생겨 포기 비용이 커짐 |
| 운동해도 성취감이 바로 안 온다 | 미션 인증 + 포인트/배지로 즉각 보상 |
| 운동 커뮤니티는 글만 많고 동기부여가 안 된다 | "응원 보내기/받기"를 포인트로 연결해 상호 격려 유도 |

### 성공 지표 (v1 프로토타입)
- 일일 미션 인증률 60% 이상
- 재방문(스트릭) 7일 유지율 체감 확인
- 응원 버튼 클릭율 (피드 노출 대비)

---

## 2. 핵심 루프 (Core Loop)

```
메이트 모집/가입
      ↓
오늘의 미션 확인
      ↓
운동 수행 → 인증샷/기록으로 인증
      ↓
메이트에게 응원받고, 응원 보내기
      ↓
포인트 적립 → 레벨업/배지 획득
      ↓
스트릭 유지 → 재방문 (루프 반복)
```

## 3. 기능 명세

### 3.1 메이트 모집 (Recruit)

**모집글 작성** (하단시트 모달)
- 운동 종류: 헬스 / 러닝 / 홈트 / 자전거 / 요가 / 등산 / 걷기 (다중선택 칩)
- 방식: 오프라인(지역 선택) / 온라인(화면공유·인증만)
- 요일: 월~일 다중선택 칩
- 시간대: 아침/점심/저녁/야간
- 모집 인원: 1~6명
- 한 줄 소개 (공개 텍스트)
- 마감일 (기본 +7일)

**모집글 목록**
- 카드형 목록 (종류 뱃지 + 요일 + 시간대 + 모집현황 `2/4`)
- 필터: 종류별 가로 스크롤 칩 / 온라인만 토글
- 신청 버튼 → 방장이 목록에서 수락/거절 (v1: 로컬 시뮬레이션)

**그룹 확정 후**
- 그룹별 공동 미션 자동 생성 (예: "이번 주 우리 그룹 인증 4회 달성")
- 그룹원 인증 현황을 홈/피드에서 실시간 확인

> **v1 프로토타입 한정**: 내가 작성한 글 + 신청은 IndexedDB에 저장. 목록에는 더미 메이트의 모집글 8~10건을 시드 데이터로 노출해서 "사람이 있는" 경험을 제공. 내 글에 더미 메이트가 일정 시간 후 자동 신청하는 시뮬레이션 포함.

### 3.2 미션 시스템 (Mission)

**일일 미션** (하루 3개 자동 제시, 프로필 설정 기반)
- 예: 30분 이상 운동 인증 / 만보 8,000보 / 스쿼트 50개 / 물 2L
- 인증 방식: 사진 업로드(카메라/갤러리) + 한 줄 메모 → 검토 없이 즉시 달성
- 당일 24시까지만 유효, 자정 리셋

**주간 챌린지** (매주 월요일 갱신, 1개)
- 예: "이번 주 4일 인증", "3일 연속 러닝", "누적 운동 3시간"
- 주간 진행바 표시

**그룹 공동 미션**
- 그룹 전원의 주간 인증 합계 목표 (예: 전원 합산 12회)
- 달성 시 그룹원 전원에게 보너스 포인트

**스트릭**
- 연속 인증일 수, 끊기면 리셋 (신경쓰지 않게 "복권" 아이템 1회/주 제공 → 스트릭 유지)

### 3.3 격려 / 소셜 (Cheer & Feed)

**피드**
- 그룹원·전체 유저의 인증 카드 타임라인 (사진 썸네일 + 미션명 + 소감)
- 최신순 / 응원많은순 정렬

**응원 보내기**
- 인증 카드에 응원 버튼 3종: 🔥파이팅 / 👍대단해 / 💪오늘도 챙겼네
- 응원하면 상대 피드에 내 응원이 표시되고, 나도 소액 포인트 획득 (일 5회 한정 — 스팸 방지)
- 응원받으면 홈에 "오늘 받은 응원 N개" 표시

> **v1 한정**: 더미 메이트가 내 인증 직후 랜덤하게 응원/댓글을 달아주는 시뮬레이션으로 "함께 하는 느낌" 제공.

### 3.4 보상 (Reward)

**포인트 정책**

| 행동 | 포인트 | 비고 |
|---|---|---|
| 일일 미션 1개 인증 | +10 | 하루 최대 3개 |
| 일일 미션 전부 완료 | +20 보너스 | |
| 주간 챌린지 달성 | +50 | |
| 그룹 공동 미션 달성 | +50 | 그룹원 전원 |
| 응원 보내기 | +1 | 일 5회 한정 |
| 응원 받기 | +2 | 무제한 |
| 7일 연속 스트릭 | +30 | 자정 정산 |
| 30일 연속 스트릭 | +100 | |

**레벨** (누적 포인트 기준, 절대 하락 없음)

| 레벨 | 이름 | 필요 포인트 |
|---|---|---|
| 1 | 🌱 새싹메이트 | 0 |
| 2 | 🔥 주니어메이트 | 150 |
| 3 | ⚡ 시니어메이트 | 400 |
| 4 | 🏅 에이스메이트 | 900 |
| 5 | 👑 레전드메이트 | 2,000 |

**배지** (획득 조건 자동 체크, 획득 시 토스트 팝업)

| 배지 | 조건 |
|---|---|
| 첫 발걸음 | 첫 인증 |
| 일주일 개근 | 7일 연속 스트릭 |
| 한 달 개근 | 30일 연속 스트릭 |
| 인싸메이트 | 응원 50회 보내기 |
| 미션 마스터 | 누적 인증 100회 |
| 단체생활 | 그룹 공동 미션 10회 달성 |

**랭킹** — 주간 포인트 랭킹 (월요일 리셋). v1은 더미 유저 12명과 경쟁하는 로컬 랭킹.

**포인트 사용처 (v2 이후)** — 배지 프레임, 스트릭 복권 추가 구매, 실물 제휴 쿠폰. v1은 적립/레벨까지만.

## 4. 화면 구조

### 전체 뼈대
- **하단 탭바 5개**: 홈 / 모집 / 미션 / 피드 / 프로필
- 하단시트 모달: 모집글 작성, 미션 인증, 배지 상세
- 모바일 우선 반응형 (360px 기준 설계, 데스크톱은 중앙 카드 컬럼 max-width 480px)

### 4.3 미션 (탭 3)
- 상단: 주간 챌린지 카드 (진행바 + 남은 일수)
- 중단: 오늘의 미션 3개 (홈과 동일 컴포넌트 재사용)
- 하단: 그룹 공동 미션 카드 (그룹원별 인증 현황 아이콘 그리드)
- 미션 히스토리 (접이식 패널, 최근 2주)

### 4.4 피드 (탭 4)
- 인증 카드 타임라인: 프로필 아이콘 / 이름 / 미션명 / 사진 / 소감 / 응원버튼 3종 + 응원 수
- 상단 정렬 토글: 최신순 ↔ 응원많은순
- 무한 스크롤 (v1은 로컬 데이터라 페이지네이션만)

### 4.5 프로필 / 보상 (탭 5)
- 내 프로필 카드: 이름, 아바타(이모지 선택), 레벨, 주간 랭킹 순위
- 누적 포인트 / 이번 주 포인트
- 배지 그리드 (미획득은 잠금 표시)
- 주간 랭킹 TOP (접이식 패널)
- 설정: 운동 종류 관심사, 미션 난이도, 알림 시간 (접이식 패널)

### 주요 모달
1. **모집글 작성** (하단시트, 앞서 명세한 폼)
2. **미션 인증** (하단시트): 사진 촬영/업로드 + 한 줄 소감 → [인증 완료] → 즉시 +10P 토스트 + "메이트에게 공유"
3. **배지 획득** (중앙 팝업): 배지 아이콘 + 축하 문구

## 5. 데이터 모델 (v1 — IndexedDB)

DB명 `yadong-db`, 스토어 목록:

| 스토어 | 키 | 주요 필드 |
|---|---|---|
| `profile` | `id` (단일 `me`) | name, avatarEmoji, level, points, weeklyPoints, streak, lastActiveDate |
| `recruitPosts` | autoInc | type[], mode, region, days[], timeSlot, capacity, joined, intro, deadline, authorId, mine |
| `applications` | autoInc | postId, applicantId, status(pending/accepted) |
| `missions` | autoInc | date, kind(daily/weekly/group), title, goal, status, verifiedAt |
| `verifications` | autoInc | missionId, photoDataUrl, memo, createdAt |
| `cheers` | autoInc | feedItemId, emojiType, fromUserId, createdAt |
| `feedItems` | autoInc | userId, userName, missionTitle, photoDataUrl, memo, cheerCounts{fire,thumb,muscle}, createdAt |
| `badges` | `id` | badgeId, earnedAt |
| `pointLedger` | autoInc | amount, reason, createdAt (포인트 변동 내역 — 레벨 계산 근거) |

**시드 데이터**: 더미 유저 12명(프로필/랭킹용), 더미 모집글 8건, 더미 피드 15건, 더미 응원 로직(내 인증 후 60% 확률로 1~3명 응원 생성).

**백엔드 전환 대비**: 모든 스토어는 v2 Supabase 테이블과 1:1 대응되도록 설계 (필드명 스네이크케이스 통일, `userId`는 v2에서 auth.uid로 치환).

## 6. 기술 스택 & 로드맵

### v1 — 프로토타입 (지금)
- **단일 `index.html`** + Vanilla JS + IndexedDB (rental-web 패턴 그대로)
- 사진 인증은 `<input type="file" capture>` → dataUrl 저장 (IndexedDB 용량 주의: 리사이즈 800px JPEG 압축 후 저장)
- 배포: GitHub 커밋→푸시→OnDev 배포
- 목적: UX·게이미피케이션 감 검증

### v2 — 실제 멀티유저 (v1 검증 후)
- **Supabase**: Auth(소셜로그인) / Postgres(테이블 v1과 동일 구조) / Realtime(피드·응원 실시간) / Storage(인증샷)
- 프론트는 v1 index.html을 컴포넌트 분리 없이 Supabase JS SDK로 마이그레이션 (IndexedDB → Supabase 어댑터 교체)
- 알림: FCM 웹푸시 (미션 리마인더, 응원 수신)

### v3 — 확장
- 포인트 사용처(배지 프레임, 복권), 제휴 쿠폰, 챌린지 상금 구조

### 일정 (제안)
| 단계 | 내용 | 예상 기간 |
|---|---|---|
| 0 | 기획안 확정 | 지금 |
| 1 | v1 프로토타입 제작 + OnDev 배포 | 반나절~1일 |
| 2 | 직접 사용해보며 피드백 | 3~7일 |
| 3 | v2 백엔드 설계·전환 | 2~3일 |

## 7. 디자인 가이드 (모바일 최적화 규칙)

- **반응형**: 360px 기준 설계, 데스크톱 max-width 480px 중앙 컬럼
- **터치 타겟**: 모든 버튼/칩 `min-height: 2.75rem`, 카드 간격 12px
- **하단시트 모달**: 작성·인증 폼은 전부 하단시트 (X 버튼 + 배경 탭 닫기, 스와이프 다운 닫기)
- **가로 스크롤 칩**: 종류 필터, 요일 선택
- **접이식 패널**: 히스토리, 랭킹, 설정 — 기본 접힘
- **컬러**: 에너지 톤 — 배경 #0F172A(다크) or 라이트 모드, 포인트 컬러 #F97316(오렌지), 성공 #22C55E, 응원 하이라이트 #FB7185
- **다크/라이트** 자동(시스템 설정 따름)
- 인증 완료 피드백: 토스트 + 포인트 적립 애니메이션 (+10P 플로팅)

## 8. 리스크 & 유의점

1. **인증샷 저장 용량** — IndexedDB는 브라우저 청소 시 소실 + 용량 제한. v1은 리사이즈 800px/JPEG 0.7로 압축, "백업 안 됨" 안내 문구 필수.
2. **더미 데이터 오해** — 실제 유저처럼 보이는 시드 데이터는 "예시" 표기를 피드 상단에 작게 표시 (신뢰 문제).
3. **포인트 인플레이션** — 응원 스팸 방지 위해 일일 한정 필수. 수치는 v1 사용 데이터 보고 조정.
4. **v2 전환 비용** — 스키마를 v1부터 Supabase 호환으로 설계해 전환 비용 최소화 (위 데이터 모델 참조).
